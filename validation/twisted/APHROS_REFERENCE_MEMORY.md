# Aphros 参考求解器的临时内存释放

128 网格扩展精度参考在上一轮首次压力求解时因系统可用内存
持续低于 2 GiB 被资源监控停止，没有完成物理步。该次峰值工作集
为 13056569344 字节，记录保存在 `timehalf64_completion` 归档中。

本次在 D 盘创建隔离构建，缩短可选 CPU 线性后端中临时对象的
存活时间。没有改动正在运行的 Aphros v7 源文件、库或可执行文件。
Cirrus 原生 GPU 压力与黏性求解路径也没有变化。

## 修改内容

`validation/aphros/build_memory_reference.py` 复制已验证的 v7 源码，
只修改实际编译使用的 `src/linear/twisted_direct.h`：

- 压缩稀疏矩阵组装结束后立即释放三元组数组。
- 缓存未命中时将矩阵存储移交给缓存对象，避免保留重复副本；
  命中时立即释放用来核对系数的临时矩阵。
- 对称性检查的转置和差矩阵在构建 AMG 层次之前析构。

所有系数、右端项、矩阵乘法表达式、标量精度、求解次序、缓存
容量和残差门槛保持不变。原始矩阵仍用于迭代修正；最终仍检查
全部原始方程，包括未固定的压力规范行。这里的 AMG 缓存包含
显式 CPU 稀疏矩阵；它属于独立参考后端，不是 Cirrus GPU 路径。

编译器用与原构建相同的宏和包含路径，对全部 48 个翻译单元
生成依赖清单。只有 `src/linear/linear.cpp` 依赖改变的头文件，
因此重新编译它，复用另外 47 个经过哈希核验的目标文件。
原始投影、对流扩散、Embed 和近壁离散的函数体经过独立核对。

## 已完成的 16 网格同配置回归

原参考：`navier_stokes_proj_n16_extended_cache_v7`。
新运行：`D:\CirrusExperiments\cirrus-amg\runs\aphros16_memory_v2`。
二者使用完全相同的配置、原始 double 几何快照和运行控制参数，
计算 dt=0.001 的一个完整物理步，有 2744 个流体单元。

现有 `check_aphros_precision_pair.py` 检查通过：

- 单元速度、去均值压力、全部面速度、壁面剪切的误差均为零。
- 单元、面、壁面、十六进制精确单元/通量和时间历史这六份
  输出文件逐字节相同。
- 两次运行均为 260 次外迭代，打印的全部外迭代误差序列相同。
- 根据实际存储的十六进制面通量，以 100 位十进制算术复算，
  质量相对 Linf 均为 1.059271919161e-12，低于原有 1e-7 门槛。

报告：`D:\CirrusExperiments\cirrus-amg\checks\aphros16_memory_pair_v2.json`。
新运行采样到的峰值工作集为 92397568 字节，最大私有内存为
84946944 字节。原运行未采用同一内存采样，因此不据此报告
内存下降比例。原、新运行墙钟时间约为 123.50、36.98 秒，但
机器同时运行其他任务，这不是独占环境性能对比。

第一次构建 v1 的求解正常结束，但清单生成器将反斜杠和斜杠
形式的同一头文件路径记成两个条目，来源检查失败。该构建和
失败日志保留，未作为验收通过的证据。修正清单生成后重新
建立 v2、重新计算并通过了完整原有检查，没有修改旧清单。
