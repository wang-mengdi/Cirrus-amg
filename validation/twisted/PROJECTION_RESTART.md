# 从完整离散状态续算

增加可选 `restart_checkpoint`，用于从已经完成并通过检查的原生
GPU 投影轨迹继续计算。绝对物理步数和时间保持连续，原来的速度、
压力、黏性预测速度和全部共享面通量均恢复。没有重新执行第一
物理步特有的初始压力处理。

当前支持一个从零初态运行完成的父轨迹；选取的时间步必须保留
完整最终场和最终内迭代 dump。暂不支持从仍在运行的父进程制作
检查点，也不支持嵌套续算。这样的范围使来源和完整性可以直接核对。

## 保存和恢复内容

`prepare_twisted_restart.py` 先对完整父轨迹执行实际共享面守恒、
完整固定点和 GPU 原始线性方程残差检查。随后从选中时间步的
`solution.csv`、最终 `iter_*/cells.csv` 和 `flux.csv` 生成二进制
状态：每个单元的 u、v、w、p、u_diff、v_diff、w_diff，后接所有
面的通量。全部使用 IEEE float64，没有缩放或重新投影。

检查点还记录父配置、绝对时间、完整时间序列前段、保留场的步号、
原始文件和执行输入的哈希，以及检查程序快照。启动时重新核对
这些内容，并逐位重建二进制状态与父结果比较。物理参数、空间
离散和数值设置必须一致；允许改变总步数和输出安排。

启动程序把已完成的时间步文件复制到新输出目录。C++ 重新建立
原生网格和求解器后，直接恢复七个单元分量及面通量，检查实际
质量守恒，并把恢复后的内存值写为 `restart_loaded.bin`。独立
检查器核对该文件与检查点逐字节相同，以及重新建立的网格、
复制的前段文件、时间和执行来源一致。

从下一绝对物理步开始执行原来的投影循环。Anderson 历史原本就
按物理步重置，续算也遵守该规则。新进程的 GPU 调用日志只描述
新计算的后段；父进程的完整调用证据单独保存，避免混淆调用计数。
最终摘要同时给出 `restart_step`、`steps_computed_this_run` 和
包含已验证前段的 `steps_completed`。

## 已完成验证

新构建关闭续算时，16 网格完整八步与先前 CGS2 构建比较通过，
两者均为 66 次内迭代；最大场量相对 L2 差为 5.33e-16。

同一新构建的另一运行从第 4 步、t=0.004 恢复，实际新计算第
5–8 步到 t=0.008。恢复状态逐字节相同，保留的前四步文件也
逐字节相同。新计算的后四步与连续运行的对应结果比较如下：

| 量 | 后四步最大相对 L2 差 |
|---|---:|
| 速度 | 1.541e-16 |
| 去体积均值压力 | 4.617e-16 |
| 切割单元速度 | 2.095e-16 |
| 壁面剪切 | 1.397e-16 |
| 全部共享面通量 | 1.405e-16 |

所有步的实际质量守恒和完整固定点通过原有门槛。后段实际执行
224 次成功 GPU 线性求解，最大原始方程相对残差为 9.337e-14，
小于原有 1e-13。恢复值的逐位一致性不等于声称后续浮点计算也
逐位相同；后段场量差异如上表所示。

12 项实际检查点损坏或不匹配测试均被拒绝，包括更改黏性、时间
步、绝对步号、时间记录、几何尺寸，缺失前段文件，截断数据，
NaN、单个浮点数改动，以及未通过检查的父轨迹。对二进制修改的
测试同时更新其文件哈希，仍因与真实父状态不符而被拒绝。

所有本轮新文件位于 D 盘。构建副本在
`D:\CirrusExperiments\cirrus-amg\builds\restart_build_v1`，
完整小算例为 runs 下的 `restart16_control_v1` 和
`restart16_tail_v1`。对应报告为 checks 下的
`restart16_control_pair_v1.json`、`restart16_tail_pair_v1.json`。

使用流程：

```text
python scripts/prepare_twisted_restart.py --run <已完成父轨迹> --step <保留完整场的步号> --output <新的D盘检查点目录>
```

复制父配置到新配置文件，设置新的 D 盘 `output`、所需总
`time_steps`，以及检查点目录中 `checkpoint.json` 的绝对路径
`restart_checkpoint`，然后使用 `run_twisted_solver.py` 启动。
与已完成的连续轨迹对比时，在 `check_twisted_time_pair.py` 中
同时使用 `--native-build-pair --restart-pair`。
