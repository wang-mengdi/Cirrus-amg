# 逐列构造切割单元重分配

`simple/EmbeddedOperators.cpp` 取消了重分配算子的全单元可编辑行。
每次只构造一个源单元对应的列，先统计每个接收行的非零项，再精确
预分配并按源单元 ID 顺序写入压缩行存储。局部重复接收单元按原邻域
顺序累计，然后写入；零项仍按旧规则省略。

原体积分数、邻域体积和重分配权重公式保持不变。两次遍历检查每个
接收行的实际写入数量。此修改不改变曲面、壁面加密、粗细交界、
黏性模型、对流算法、GPU 求解器或数值验收门槛。

重分配用于原 Aphros 算法的切割单元源项处理。投影路径没有打开
黏性重分配，但仍保留原对流重分配，因此不能直接删掉该算子来省内存。

## 系数与流动验证

源码范围检查确认重分配之外的代码保持不变，并逐项核对体积分数、
邻域体积和原权重公式。真实原生 16/64 网格上，旧、新 CPU 探针的
12 组模式全部通过；156 份稀疏系数、边界权重与守恒/解析检查文件
逐字节一致。64 级含 136632 个流体单元、1536 个粗细交界面。

正式 MSVC/CUDA 程序的 CPU 16、GPU 16、GPU 64 均完成两个物理步。
CPU 最终及中间 CSV 逐字节相同；GPU 的速度、压力、切割单元速度、
壁面剪切、共享面通量五类量最大相对 L2 差分别为 `2.25450e-16`
和 `1.12196e-14`。完整内迭代固定点、实际质量守恒和全部线性精度
检查通过原门槛。这是存储修改的回归，不构成新的空间收敛结论。

回归脚本 v1 在启动求解器前因范围检查文件名指向不存在的 v2 而失败；
修正路径后使用 v2 脚本继续。失败的 `passed=false` 记录保留。
