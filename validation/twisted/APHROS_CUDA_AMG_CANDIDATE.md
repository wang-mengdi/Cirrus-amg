# 独立 Aphros 的可选 CUDA AMG 后端

该候选只改变独立 Aphros 验证程序的近似线性求解后端，不修改 Cirrus
的八叉树、曲面切割、离散方程或 matrix-free GPU 算子。Aphros 的压力
与隐式黏性方程仍由 Aphros 自己组装；不能将本候选中的 CSR 矩阵解释为
Cirrus 生产求解路径重新改用显式矩阵。

默认关闭的 `APHROS_TWISTED_CUDA_AMG` 选项，须与原有 AMG 和双精度近似
后端选项同时开启。它调用 AMGCL 的 CUDA 后端，使用 smoothed aggregation、
SPAI0、对称系统 CG / 非对称系统 BiCGStab，近似解容差 `1e-13`、最多
500 次线性迭代。原始扩展精度矩阵、右端项、兼容性和压力基准处理、
最多六次扩展精度残差修正及最终所有原方程行的检查均保留。原有最终
拒绝条件 `residual > 10 * tolerance` 未改动；近似解的残差估计不能替代它。

MinGW Aphros 保留 `long double`，MSVC/CUDA DLL 只接收 32 位 CSR 索引、
双精度系数和向量。C ABI 不传递 Eigen、STL 或扩展精度对象。每次解都
从零近似解开始，矩阵缓存包含 CUDA 选择标志；日志 `cuda_amg.csv`
记录真实构建与求解调用，`mixed_precision.csv` 记录原方程残差检查。

## 代码及构建

- `validation/aphros/cuda_amg_bridge.cu`：独立 AMGCL CUDA DLL。
- `validation/aphros/cuda_amg_client.h`：Aphros 侧 C ABI 客户端，默认路径
  不装载 CUDA DLL。
- `validation/aphros/build_cuda_amg_bridge.py` 与
  `build_cuda_amg_reference.py`：独立 D 盘构建及源代码/对象哈希检查。
- `scripts/run_aphros_cuda_amg_reference.py`：从已完成零初值参考复制原始
  输入，记录 DLL 依赖、资源和运行来源，保留原 CPU 运行器。

实际 DLL 构建为 `D:/CirrusExperiments/cirrus-amg/builds/aphros_cuda_amg_bridge_v2`，
使用 CUDA 12.9、`sm_86` 和共享 CUDA runtime，SHA-256 为
`ecebfd16920ac1bffb24bd99f9768c8fbf117c5b751b2f4bce5f01d11c62696a`。
第一次 DLL 构建的 runtime 混用警告已消除，其日志保留。实际 Aphros
构建为 `builds/aphros_cuda_amg_v2`，可执行文件 SHA-256 为
`0f0fbfd5207c34b1dbadd25e26cf28bd22492ba58b146bcb2d2001a8a2fdd933`。
只重新编译 `src/linear/linear.cpp`，47 个对象经依赖扫描及哈希验证后复用。
第一次 Aphros 构建在迭代计数的元组类型上编译失败，保留失败源码和日志；
修正返回类型后在新目录重新构建。
