# 压力面算子直接组装及原生 128 内存实测

上一轮原生 128 构造实测中，压力矩阵和粗细交界 Taylor 行的
组装产生了最大的工作集峰值。本次将这部分独立为
`simple/ProjectionAssembly.h`，由 `ProjectionSolver.cpp` 调用。
保留原有离散系数，减少全局原始三元组和 Eigen 转换时的副本。

散度按面逐列填入，每个内部面保留两个有符号系数；周期接缝处
按单元编号排序。紧致梯度先统计每列容量，再按面编号递增填入，
最后压缩。粗细交界的梯度修正和两侧 Taylor 行仅为交界面分配
临时行，在局部按原先顺序合并重复系数，再直接写入有序稀疏
存储。每份临时行在矩阵拥有系数后释放。

这里保留第一个系数的原值、后续相加次序及显式零项，包括负零，
与原有 `setFromTriplets` 行为一致。它与曲面算子已有的零项
过滤规则不同。相关行为核对了实际使用的 Eigen 5.0.1 源码。

GPU 压力/黏性算子及 AMG 没有改变。CPU 稀疏算子继续承担现有
输运、延迟项、残差及诊断工作；GPU 仍使用原有 matrix-free
求解路径。新旧 GPU 审计程序的 SHA-256 完全相同。

## 系数和实际流场验证

新版 `builds/ordered_projection_storage_v1` 两个目标编译通过，
已有编译源中仅 `ProjectionSolver.cpp` 改变，新增头文件
`ProjectionAssembly.h`。主程序 SHA-256：
`7353fca03674dd1f448ee2719c49396adcc62c4f430fab8961c7b01885a042d2`。

`validation/projection_assembly_test.cpp` 使用实际保留的 uniform 16
和 adaptive 64 网格、面梯度及插值 dump，并在同一个进程中比较
生产头文件中的新组装与测试内保留的旧三元组算法。实际 64 网格
包含 136632 个流体单元、421004 个面和 1536 个粗细交界面。
两份实际网格各比较八个完整矩阵：散度、紧致梯度、界面修正、
两侧 Taylor 行、紧致压力、延迟压力及完整梯度。

16 个完整矩阵的存储索引和 double 系数字节均一致；另有 17 个
合成矩阵比较，覆盖重复相加、正负零、空面集、周期反向编号、
自连接和边界面，索引容量溢出拒绝也通过。该测试用 MinGW 和
Eigen 5.0.1 编译，是同进程算法比较；它不是旧、新生产程序各自
导出的压力矩阵比较。另用实际 MSVC 生产程序完成流场回归。

CPU 16、GPU 16 和 GPU 64 各推进两物理步，与旧版
`builds/ordered_operator_storage_v1` 已保存的同配置轨迹比较。
固定点、真实线性残差和实际面通量守恒均执行已有门槛。

| 回归 | 结果 |
| --- | --- |
| CPU 16 | 每步四份最终 CSV 和六份中间 CSV 逐字节一致 |
| GPU 16 | 五类场量最大相对 L2 差 `2.1634e-16`；132 次线性求解 |
| GPU 64 | 五类场量最大相对 L2 差 `1.0900e-14`；466 次线性求解 |

五类场量为速度、去压力常数后的压力、切割单元速度、壁面剪切
向量和共享面通量。原有比较门槛仍为 `1e-6`。新 GPU 64 最大
接受线性相对残差为 `9.961516954323681e-14`，满足 `1e-13`。
CPU 默认关闭构造内存记录，GPU 开启；23 个阶段记录检查通过。
GPU 64 整段两步回归峰值工作集由 728.26 MiB 变为 730.15 MiB，
没有改善，不能以构造内存的下降宣称完整流动峰值下降。

## 原生 128 的真实构造比较

完成上述回归后，新版实际运行相同 128 扭曲管的 `operator_only`
配置，包含完整 GPU 压力/黏性及原生 AMG 初始化。程序正常退出，
未推进物理时间或定常外迭代。790216 个流体单元、2431944 个面、
49152 个压力交界面保持一致。

新旧单元 CSV、面 CSV、曲面算子检查、交界检查及两份材料诊断
文件共六份均逐字节一致。输入哈希和运行完成记录检查通过。
新构造的 23 个阶段记录完整，内存保护未触发。

| Windows 进程计数 | 旧版 | 新版 | 相对变化 |
| --- | ---: | ---: | ---: |
| 累计峰值工作集 | 3136729088 B / 2.92 GiB | 2771595264 B / 2.58 GiB | -11.64% |
| 累计峰值提交计数 | 4325613568 B / 4.03 GiB | 4332564480 B / 4.04 GiB | +0.16% |

峰值提交计数基本不变。它不是磁盘写入量或显存占用。以下阶段
数据单位为 MiB；累计峰值也包含记录点之间已经释放的临时分配。

| 构造节点 | 旧版当前 / 累计峰值工作集 | 新版当前 / 累计峰值工作集 |
| --- | ---: | ---: |
| 曲面算子返回 | 1557.02 / 2321.49 | 1553.96 / 2321.87 |
| 压力矩阵及 Taylor 行完成 | 2778.62 / 2991.42 | 2111.04 / 2321.87 |
| 压力组装临时数据释放 | 2061.26 / 2991.42 | 2061.22 / 2321.87 |
| GPU 网格场初始化返回 | 2164.26 / 2991.42 | 2164.01 / 2643.20 |
| 构造结束 | 2199.51 / 2991.42 | 2199.71 / 2643.20 |

压力组装期间不再超过此前曲面算子的峰值；新版整体构造峰值
发生在 GPU 网格场初始化阶段。这里只定位阶段，未将峰值精确
归因到某个内部数组。构造结束的驻留工作集基本不变。

控制器在等待阶段检查至少 7 GiB 可用物理内存；这是在旧版同
配置 2.92 GiB 构造峰值已测得后设置的余量。随后重新校验输入
文件，实际启动记录为 6.84 GiB，因此不能声称启动瞬间仍满足
7 GiB。运行期间观察到的最低可用内存为 4.71 GiB。若低于
3.5 GiB，仅在没有其他原生 GPU 实验时允许停止本探测。实际
未触发停止，原始 Aphros 128 CPU 参考计算持续运行。后续更大
实验需要在校验输入后、启动前再次检查可用内存。

64→128 的近壁速度、WSS 和流量网格检查仍有失败项，目标继续。
没有运行原生 256 构造或流场，也没有证明其完整内存需求可满足。
