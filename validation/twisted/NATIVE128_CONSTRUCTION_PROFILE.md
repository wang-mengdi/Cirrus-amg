# 新版原生 128 完整算子构造实测

完成物理控制及终态对比后，实际运行
`builds/ordered_operator_storage_v1/simple_channel.exe`，使用相同
128 扭曲管、原生壁面细化、完整 GPU 压力/黏性及 AMG 配置，开启
`operator_only` 和构造阶段内存记录。没有推进物理时间或进行
定常迭代。程序正常退出，输入不变，内存保护没有触发。

输出 `runs/ordered_operator_storage_only128_v1` 的单元、面、
曲面算子检查、粗细交界检查及两份材料算子诊断文件，均与已完成
的 `steady_outer128_v1` 对应文件逐字节一致。实际 23 个构造阶段
记录齐全，最终压力交界面数为 49152。

整个进程的累计峰值工作集为 3136729088 字节（约 2.92 GiB），
峰值提交计数为 4325613568 字节（约 4.03 GiB）。提交计数不是
磁盘写入量或显存占用。工作集取样不能精确归因到某个数组，也
不包含完整流动中尚未发生的分配。

实测最大的构造峰值出现在压力矩阵和粗细交界 Taylor 行组装。
曲面算子返回后，压力组三元组准备期间当前工作集增加约
879 MiB；随后释放压力组装临时数据，当前工作集减少约 717 MiB。
这为下一步减少该处三元组和转换副本提供了实际依据。

本次没有旧版同配置 128 的阶段测量，不能据此给出 128 的改善
百分比；此前完整流动的峰值也不能作为构造阶段的直接对照。
没有运行原生 256 构造或流场，也没有证明其内存需求满足限制。

探测控制器先等待完整物理控制验证通过，并要求启动时至少
7.5 GiB 可用物理内存。若可用内存低于 3.5 GiB，仅在没有其他
原生 GPU 实验时才允许停止本探测；实际未触发。原始 Aphros
128 参考保持运行。完整记录在 `checks/ordered_operator_storage128_v1`，
小型提交证据在 `results/native128_control_completion`。
