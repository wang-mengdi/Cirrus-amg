# Aphros 三项 AMG 缓存的完整数值对照

使用相同的冻结 Aphros 可执行文件、几何、初始速度和求解设置，
将缓存容量由 1 改为 3。当前后端为 AMG；`factor-cache` 沿用旧名，
并不表示采用 LDLT。缓存命中要求压缩矩阵的数值、零的符号和
稀疏结构完全相同，右端项、初值、线性容差和调用顺序保持不变。

16 级扭曲细管使用 Proj、BCG、隐式黏性、`Ndiff=1`，128 个物理步，
`dt=0.005`，终止时间 0.64。2026-09-09 12:22:14 UTC 完成严格核验：

| 项目 | 一项缓存 | 三项缓存 |
| --- | --- | --- |
| 线性求解调用 | 15638 | 15638 |
| 缓存命中 | 6400 | 15635 |
| AMG 重建 | 9238 | 3 |
| 完成物理步 | 128 | 128 |
| 观测耗时（秒） | 833.538896 | 585.116964 |
| 峰值工作集（B） | 46399488 | 67997696 |

速度/压力单元文件、面通量、壁面剪切、两份扩展精度单元/面文件、
时间历史共六份输出逐字节一致，完整外迭代误差序列也相同。双方
用存储的原始扩展精度通量重新计算质量守恒，均通过原门槛。
全部线性调用的系统名称、行数及非零数序列相同。

三次重建后全部命中表明，本次运行只遇到三份不同的压缩矩阵。
两项缓存不足以保留这个交替序列，见 [双缓存实验](APHROS_TWO_ENTRY_CACHE.md)。
表中时间是在不同并发任务下观测的，不作为独占性能基准。

配置只存在冻结运行器带来的 `tmax` 文字差异：`0.64` 与
`0.64000000000000001`。沿用独立检查器验证唯一的文本替换、其他
全部配置相等、编译代码使用 `Map<double>`、解析 binary64 值相同，
以及全部实际时间记录逐字节相同。没有修改任一原始配置或正式
冻结比较器，也没有放宽场量或守恒门槛。

已完成的 `aphros64_initial_native_v1` 原本就使用三项 AMG 缓存和
`Ndiff=8`。本次小算例验证的是当前 `aphros_lazy_centers_v1` 冻结
可执行文件的容量切换；不能用它估算 128 级额外缓存的内存开销。
本次缓存对照没有修改或重启原 CPU Aphros 128，也未启动 128 级
三项缓存运行。之后为 256 网格安排的有时限内存调度另行记录，
不改变本次已完成对照的数值结论。
