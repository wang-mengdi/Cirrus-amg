# 精确预留切割面存储并提前释放构造数据

`simple/EmbeddedMesh.cpp` 现在先用原有裁剪路径统计保留的流体面，
加上去重后的壁面数，一次预留最终面数组；随后按原顺序再次遍历
背景面并填充。两次遍历都执行原有背景网格验证，计数和填充共用
同一裁剪实现。填充结束检查面数与预期相等、数组容量没有增长。
代价是额外一次背景面的遍历、查找及裁剪，没有宣称运行加速。

背景单元、旧编号映射和参考面索引放入局部作用域，在裁剪完成后
立即销毁；随后释放参考面记录的数组或只读映射。壁面构造仍需要
的参考单元、壁面记录及细单元编号映射继续保留。原生八叉树、
浮点计算顺序、切割几何、壁面处理及压力/黏性算法保持原样。

## 实际验证

旧版 `builds/mapped_geometry_v1` 与新版 `builds/exact_face_storage_v1`
的编译源快照只有 `simple/EmbeddedMesh.cpp` 不同。Windows 主程序
及 GPU 审计目标均编译成功，新主程序 SHA-256：
`7383125f522bac8dd1cdfd3f1d70f2c3acab732a027c2f00b2a5ae1c4b527aeb`。

两版实际程序通过 4 项 JSON 输入检查和 14 项二进制输入检查，
覆盖记录重排、重复保留规则、重复单元及不一致周期面拒绝，
以及文件头、尺寸、截断、缺失文件、NaN 等异常。有效变体最终
网格逐字节一致，无效输入由导入器按相同规则拒绝。

真实 128 导入得到 790216 个流体单元、2431944 个面和 49152 个
粗细交界面。单元及面 CSV 与已完成的 `steady_outer128_v1` 网格
逐字节一致。日志确认最终面数组大小和容量均为 2431944，
占 408566592 字节；填充过程未扩容，体积及面积向量闭合检查通过。

CPU 16、GPU 16、GPU 64 各重新运行两物理步，与已有的旧版实际
运行比较。CPU 最终四份场/通量 CSV 和每步六份中间 CSV 均逐字节
一致。GPU 的速度、压力、切割单元速度、壁面剪切向量及共享面
通量最大相对 L2 差为 `2.943e-16`（16）和 `1.150e-14`（64），
通过原有 `1e-6` 回归门槛。固定点和实际质量守恒检查通过。
新 GPU 64 完成 476 次线性求解，最大接受真实相对残差
`9.962e-14`，仍满足 `1e-13`。这些是两步存储等价性检查，
不构成新增的 Aphros 对齐、定常或网格收敛结论。

## 内存测量范围

128 几何导入的 Windows 进程累计峰值，单位 MiB：

| 指标 | 旧版只读映射 | 新版精确预留及提前释放 |
| --- | ---: | ---: |
| 峰值工作集 | 1736.59 | 1604.85 |
| 峰值提交计数 | 2106.21 | 1867.30 |

工作集减少 131.74 MiB（7.59%），提交计数减少 238.91 MiB
（11.34%）。提交计数不是磁盘写入量，也不是 GPU 显存占用。
GPU 64 完整两步运行的峰值工作集为 730.02 和 730.22 MiB，
基本不变；提交计数为 1300.23 和 1295.35 MiB。因此实际测得
的改善集中在几何构造，不能推断完整大规模流动的内存同比下降。

尚未运行 256 原生网格构造或流场。256 参考表、背景和最终单元
增长比例不同，不能由本次 128 测量断言 256 可放入当前可用内存。
64→128 的近壁速度、壁面剪切和空间收敛失败记录保持有效。
