# 用实际进程记录定位算子构造内存

为了判断更细近壁网格的内存限制，增加可选环境变量
`SIMPLE_CONSTRUCTION_MEMORY`。设置该变量时，生产程序在曲面
算子及 projection 构造的 23 个阶段打印 Windows 当前工作集、
累计峰值工作集、当前私有提交量和系统可用物理内存，单位字节。
不设置该变量时不执行内存查询，也不打印这些记录。

实现位于 `simple/ConstructionMemory.h`，观测点位于
`simple/EmbeddedOperators.cpp` 和 `simple/ProjectionSolver.cpp`。
查询使用当前进程的 Windows 内存计数，不清空工作集、不等待
GPU，也不修改数值选项或内存分配策略。它没有测量显存，阶段
记录不是各数组的精确占用归属；累计峰值可能出现在两个记录点
之间。非 Windows 路径只报告不可用，未进行非 Windows 编译验证。

Windows RPC 头文件会把已有 CFD 变量名 `interface` 定义为宏。
首次构建因此失败，记录保留在 `builds/construction_memory_v1`。
最终版本用宏 push/pop 恢复包含头文件前的含义，没有重命名
数值代码变量。`builds/construction_memory_v2` 的主程序和 GPU
审计目标均编译成功。新主程序 SHA-256：
`1ae1acb94e7af07817ae16fa6826f6025cf13410d86bbb675474fa8ba68c6bc3`。

## 实际 64 构造观测

相同三维扭曲细管、原生自适应网格及完整 GPU 压力/黏性选项下，
阶段工作集如下，MiB：

| 阶段 | 当前工作集 | 到该阶段的累计峰值 |
| --- | ---: | ---: |
| projection 开始 | 235.22 | 364.58 |
| 曲面算子查找表和邻域准备好 | 326.05 | 364.58 |
| 曲面算子组装行准备好 | 443.82 | 443.82 |
| 面插值及梯度矩阵完成 | 482.39 | 511.04 |
| 黏性矩阵完成 | 532.34 | 545.88 |
| z 方向单元梯度完成 | 567.19 | 579.41 |
| 曲面算子构造返回、临时数组释放 | 340.87 | 579.41 |
| 压力矩阵及 Taylor 行完成 | 457.93 | 579.41 |
| GPU 完整算子初始化后 | 457.57 | 579.41 |

本次构造累计峰值出现在曲面算子组装阶段，而不是 GPU 初始化
阶段。构造返回前后的当前工作集减少约 219.71 MiB；这支持下一步
检查同时存活的组装行、稀疏矩阵转换和查找邻域临时数据。
Windows 堆可能保留已释放内存，所以差值不能精确归因到某个数组。
完整流动中的峰值还包括后续迭代存储，不能用此表代替完整求解
的峰值测量。本次完整两步 GPU 64 的峰值工作集为 730.43 MiB，
高于构造阶段的 579.41 MiB。这里没有声称 128 或 256 能按单元
数量简单线性外推。

## 回归与范围

CPU 16 默认关闭记录，GPU 16、64 开启记录，各运行两物理步，
与已验证的 `builds/exact_face_storage_v1` 实际运行比较。记录
开启状态由本轮生产脚本保存，原运行包装器的环境清单没有列出
这个新变量。独立检查读取实际日志，验证 CPU 没有记录、两个
GPU 运行都具有全部 23 个有效阶段，且累计峰值单调不减并与
外部 Windows 进程计数相容。

流场回归使用已有的速度、压力、切割单元速度、壁面剪切向量、
共享面通量、固定点、质量守恒及真实线性残差门槛。实际数值结果
记录在 `results/construction_memory/checks`，阶段观测记录在
`results/construction_memory/observations`。这是观测功能验证，
没有新增 Aphros 对齐、定常精度或空间收敛结论。

三组两步回归均通过。CPU 最终四份场/通量 CSV 和每步六份中间
CSV 逐字节一致。两个 GPU 运行的五类场量最大相对 L2 差分别为
`2.930e-16`（16）和 `1.106e-14`（64），低于原有 `1e-6` 门槛。
新 GPU 64 完成 462 次线性求解，最大接受真实相对残差为
`9.962e-14`，保持 `1e-13` 门槛。默认关闭和全部阶段记录检查通过。

所有完整构建和运行位于 `D:/CirrusExperiments/cirrus-amg`。
原始 Aphros 128 和原生时间控制继续独立运行。64→128 的近壁
速度、壁面剪切及空间收敛失败仍待解决；这次改动只是为更细网格
所需的内存改进提供实测依据。
