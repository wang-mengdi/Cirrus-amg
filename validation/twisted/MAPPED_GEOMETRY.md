# 只读映射二进制参考几何

`simple/EmbeddedMesh.cpp` 的 Windows 二进制导入路径改用只读文件
映射，避免先把完整参考单元、面和壁面表复制到私有数组。原来的
JSON 输入及非 Windows 路径仍使用数组。实际编译、输入异常和
流场检查均在 Windows 完成，没有声称已测试非 Windows 路径。

三个记录表仍提供相同顺序的 double 数据。查找索引、重复记录
保留规则、体积累加顺序、原生八叉树、切割处理和离散算法不变。
每条记录仍经过有限性检查。文件头、列数、行数、文件大小、整数
溢出及记录容量检查保留；记录通过检查后才供几何构造使用。

映射以 `GENERIC_READ`、`PAGE_READONLY`、`FILE_MAP_READ` 打开，
整个导入期间保留不允许写共享的文件句柄。局部 RAII 对象负责
释放视图、映射对象和文件句柄，包括构造异常路径。映射的记录
在查找索引销毁之后释放。该改动没有修改压力/黏性求解算法，也
没有把文件映射当作 GPU 矩阵或改变 AMG 后端。

## 实际验证

旧版 `builds/streamed_geometry_v1` 与新版 `builds/mapped_geometry_v1`
的编译快照只有 `simple/EmbeddedMesh.cpp` 不同。主求解器和 GPU
审计目标均编译成功，新主程序 SHA-256 为
`b4ed31a25ae231851d0edb8faa8a6a5d816317fac08c928385879bb7701229e3`。

两版生产程序都通过以下真实导入检查：

- JSON 的四项检查：记录打乱、重复首条保留、重复单元拒绝、
  不一致周期开口拒绝。
- 二进制的相同四项检查，以及错误 magic、字节序、列数、极大
  行数、空文件、截断文件头、截断数据、尾部多余数据、缺失文件
  和 NaN，共 14 项检查。

有效变体的最终网格逐字节一致，无效变体由两版按原规则拒绝。
这些检查直接运行导入器，不通过运行包装器的哈希检查提前拦截
损坏输入。

真实 128 二进制导入也通过：790216 个流体单元、2431944 个面，
单元和面 CSV 与已完成的 128 定常运行逐字节一致。

CPU 16、GPU 16 和 GPU 64 各完成两个物理步的流场回归。64 的
两版都重新运行，使用同一份现有 `packed_n64_shift` 输入；16
对照使用此前保存的同一旧程序运行。CPU 最终四份场/通量 CSV
以及每步保存的六份中间 CSV 均逐字节一致。GPU 的速度、压力、
切割单元速度、壁面剪切向量和共享面通量最大相对 L2 差分别为
`3.042e-16`（16）和 `1.197e-14`（64），通过原有 `1e-6` 回归
门槛。固定点和实际质量守恒检查通过。新 GPU 64 完成 468 次
线性求解，最大接受真实相对残差 `9.962e-14`，保持 `1e-13` 门槛。
这验证存储改动的等价性，未新增定常、时间步或空间精度结论。

## 内存测量的范围

128 几何导入的 Windows 进程累计峰值，MiB：

| 指标 | 旧版数组读取 | 新版只读映射 |
| --- | ---: | ---: |
| 峰值工作集 | 1737.45 | 1736.59 |
| 峰值提交计数 | 2405.98 | 2106.21 |

提交计数减少约 299.77 MiB，工作集基本未变。文件页仍会进入物理
内存，因此这项修改不能证明 256 完整导入或求解能放入当前可用
RAM。提交计数不是磁盘写入量，也不能作为显存需求指标。

GPU 64 两物理步的峰值工作集为旧版 729.97 MiB、新版 730.02
MiB；峰值提交计数为 1298.83 和 1300.23 MiB。完整运行的峰值
也基本未变，没有宣称该修改减少了完整流动的物理内存。

所有构建、完整实验和大文件保留在 `D:/CirrusExperiments/cirrus-amg`。
检查目录为 `checks/mapped_geometry_regression_v1`、
`checks/mapped_geometry_{legacy,packed}_guards_v1` 和
`checks/mapped_geometry128_v1`；小型提交证据在
`results/mapped_geometry`，包含实际源快照和大文件哈希。
原始 Aphros 128 参考和原生物理时间控制运行保持独立。后续仍需
减少完整网格/算子构造的临时存储，并完成更细流场与近壁空间
收敛验收；这项存储改动本身不提高近壁离散精度。
