# Aphros 构造缓存释放与缓存容量验证

本轮处理 128 网格独立参考解的内存瓶颈。新的实现只位于验证
程序中，原生 Cirrus 八叉树和 GPU 算子没有变化，完整扭曲管道、
切割几何、物性、时间步及原参考求解门槛保持不变。

## 实现

`validation/aphros/twisted_cold_storage.h` 在几何导出完成、原 Proj
构造函数复制初始速度、时间诊断保存初值之后，释放以下存储：

- 驱动程序的初始 level set 和初始速度。
- Embed 构造用 level set、网格面的可视化多边形、单元几何质心。
- 当前固定投影算例不使用的壁面距离及最近壁面位移缓存。

求解实际使用的体积、面积、法向、壁面平面、面中心和邻域体积
均保留。原 `GetFaceOffset` 等通用接口可能间接访问单元质心，
所以隔离头文件为已释放字段的 getter 加入明确报错：若某个
其他配置仍需要它们，程序会失败，不会读取空数组或返回假值。
该选项默认关闭，不能据当前算例验证把它视为所有 Aphros 模型
都适用的全局优化。

`prepare_cold_storage_reference.py` 复制已验证的独立源树，只修改
驱动程序及 `solver/embed.h` 的友元和访问检查，加入辅助头文件。
原 `proj.ipp/proj.h/embed.ipp/approx_eb.ipp/convdiffi.ipp/convdiffe.ipp`
保持逐字节一致；原梯度拟合、投影、对流和黏性更新没有修改。
全部 48 个翻译单元重新构建，仍关闭 fast-math 和浮点收缩。

实际执行文件为
`D:/CirrusExperiments/cirrus-amg/builds/aphros_cold_storage_v1/twisted_extended.exe`，
SHA256：
`22d22b721570a20954c1928255acf633ff71e3aa10b8d73c18e93fc800acd895`。

运行器 `run_aphros_cold_storage_reference.py` 完整重放参考输入和
环境，显式记录开关、源文件哈希、实际进程及资源。可用内存
持续低于 2 GiB 达 10 秒时，只停止身份已核实的新 CPU 参考进程。
资源停止不能算数值失败，也不能算完整解通过。

`run_aphros_cold_cache_reference.py` 额外允许记录并调整原后端的
缓存容量。容量 1 会在需要不同算子时重新构建原预条件器；矩阵
系数、求解顺序、标量类型、线性门槛和原始方程残差检查不变。
此调整作用于 Aphros CPU 参考后端。

## 已完成的 16 网格验证

三次运行均使用同一份完整原几何，dt=0.001，完成一个物理步，
以 `runs/aphros16_initial_off_v1` 为原参考。原有完整比较器检查
真实构建来源、原算法函数体、实际加载几何、全部时间记录、
质量守恒和场值，门槛保持不变。

| 运行 | 缓存容量 | 峰值工作集（字节） | 六份输出逐字节相同 |
|---|---:|---:|---|
| `aphros16_cold_storage_off_v1` | 3 | 80482304 | 是 |
| `aphros16_cold_storage_on_v1` | 3 | 75337728 | 是 |
| `aphros16_cold_cache1_v1` | 1 | 53362688 | 是 |

六份输出包含速度/压力、面通量、壁面剪切、精确存储的单元/面
数据及时间变化记录。三次都保持原来的 260 次外迭代和完整
误差序列；所有比较场的相对 L2 差为零。实际存储通量复算的
质量相对 Linf 均为 1.0592719191611579e-12。

对应报告为 `checks/aphros16_cold_storage_off_pair_v1.json`、
`checks/aphros16_cold_storage_on_pair_v1.json` 和
`checks/aphros16_cold_cache1_pair_v1.json`。

释放操作发生时，16 网格工作集实测减少 4976640 字节。单份
缓存版本的观测运行时间约 85.9 秒，三份缓存释放版本约 44.2 秒。
这些是与其他任务并行时的资源记录，不是独占性能基准。

## 64/128 网格的当前证据

`runs/aphros64_cold_storage_on_v1` 已完成完整 64 网格第一步
回归，仍使用原来的 8 次黏性内迭代。释放阶段的实际工作集从
942837760 降到 765501440 字节，减少 177336320 字节。
最终峰值工作集为 1671479296 字节，最大观测 private bytes 为
1956872192 字节。六份完整输出与 `aphros64_zero_reset_v1`
逐字节一致，39 次外迭代的误差序列完全相同；实际通量质量
相对 Linf 为 5.279026686027291e-10。报告为
`checks/aphros64_cold_storage_pair_v1.json`。这证明本项存储修改
保持第一步结果，仍不代表最终定常精度通过。

`configs/complete_cold_storage64_v2.py` 已核实具体进程身份，
在真实完成后调用原完整比较器并通过。首次观察器因命令行使用
相对脚本路径而未通过身份检查，未改变运行；v2 按实际工作目录
解析路径后验证。观察器不重启求解器。

`profile_aphros_geometry_storage.py` 只读取原二进制几何。完整
128 网格仍为 256×128×128，含 1076936 个流体单元和 87248 个
切割单元；实际原始索引存储形状为 261×133×133。
按 MinGW 的 16 字节 long double 存储，待释放字段及多边形数据
合计 1252849512 字节。16 网格的同类估计已与释放器实际记录的
逐字段大小完全一致。这个数不是 128 网格实测峰值节省，也
不能单独证明完整 128 参考解能放入当前内存。

同一清点还识别出普通笛卡尔网格的单元/面中心数组理论占用
886431168 字节；本项构造缓存修改没有改变坐标数组，也没有
裁剪任何网格或流体区域。后续坐标计算优化的独立证据见
[APHROS_LAZY_CENTERS.md](APHROS_LAZY_CENTERS.md)。

原生 128 续算已完成第 13 步并进入第 14 步。第 13 步为 32 次
外迭代，完整内迭代固定点残差 1.4523965490482582e-9，程序报告
的质量相对 Linf 为 9.671554129465377e-11。流量、平均壁面剪切、
最大速度与原父运行的该步标量一致到舍入量级。该步配置没有
保存完整场，因此此项只记录推进及标量对照，不冒充完整场
独立检查；最终动量定常残差仍约 0.0409，尚未定常。

本轮证据在 `results/aphros_cold_storage_checkpoint`，大型输入
和运行输出留在 D 盘。独立 Aphros 定常对齐、128 参考的完整运行、
空间收敛和最终近壁精度验收仍未完成，goal 保持进行中。
