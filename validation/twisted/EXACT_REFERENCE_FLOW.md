# 扩展精度参考的实际流动检查

本记录延续 `EXTENDED_REFERENCE.md`。仍保留原八叉树及扭曲三维细管，
未改变压力、黏性、对流或时间推进公式，未降低物理验收阈值。

## 已完成的比较

`navier_stokes_proj_n16_extended_exact_v5` 实际完成 dt=0.001 的一步。
与 native `ours_proj16_anderson_failure_v1/step_0001` 比较通过：速度
相对 L2 为 7.122e-10，压力 2.531e-10，切割单元速度 1.482e-9，壁面
剪切 3.801e-9，截面流量 1.074e-10；全部共享面通量也通过原有阈值。

`TwistedExactFlowDump` 只读输出实际存储的单元速度、压力、体积以及
面面积和通量，使用十六进制浮点格式保存所有有效位。原十进制输出
不变。实际运行报告 64 位尾数，存储占 16 字节；这不是 128 位有效
精度。Python 检查器使用 100 位十进制算术直接累加实际面通量，未
重算或替换压力表达式。单步相对散度 Linf 为 1.0593e-12。

几何索引、原始体积/面积、普通输出与完整精度输出的对应、最终物理
时间和两份周期缝通量均被检查。原算法独立计算周期缝的两份通量，
16 网格原 double 控制中存在约 8.125e-16 的相对差异，故不能要求
逐位相同。检查器保持既有 1e-12 周期缝阈值，同时要求选用任意一份
缝通量得到的相对散度均低于 1e-7。没有按舍入估计豁免小切割体积。
最初要求周期缝逐位相同的失败诊断和当时源码均保留。

对已完成的原 double 场做十六进制重放（不是新流动）：16 控制仍然
通过，64 控制仍以 2.79278074013e-7 的相对散度失败。这证明新检查
没有把已知守恒问题变成通过。最终检查器及控制数据均记录哈希。

`navier_stokes_proj_n16_extended_amg_v4` 的 dt=0.001、8 步也实际完成，
与 native 对应第八步的场量、近壁速度、剪切及全部面通量比较通过。
该较早版本只有普通 double 导入检查，报告明确保留这一精度范围。
它支持完整短轨迹的实现对照，不能作为大网格稳态或网格收敛证明。

`compare_twisted.py --extended-reference` 显式验证隔离构建、实际
可执行文件、所有已记录的构建输入/目标文件、原始方程体、完整物理
时间序列和来自原 double 静态库的几何快照。默认原 double 路径
未改变，其既有 16 比较回归通过。

## 编译优化与缓存

v5 与 v6 使用相同准备源码，分别以 O1/O3 编译，均关闭 fast-math
和浮点收缩。两次完整单步的 260 个外层迭代误差、最终普通/十六
进制场量、壁面剪切和时间诊断全部逐字节相同，守恒均通过。
观测墙钟时间约 392.5 秒和 314.9 秒；同时有其他任务运行，因此
不是独占机器性能基准。

v6 的实际三迭代诊断中，18 次线性求解全部未命中缓存。原 double
后端按原始字节比较矩阵系数；转换为 long double 后会比较到没有
数值含义的填充字节。v7 的可选 scalar-value-cache 比较精确系数
值并区分正负零，索引仍逐字节比较；无近似匹配，不改变矩阵或右端。

同一实际诊断中，v7 只在首次遇到三套算子时未命中，后续 15 次
命中。前三次迭代误差完全相同。实际 C++ 输入只改变缓存比较所在
的 `linear/twisted_direct.h`。这些诊断刻意设置三次迭代上限并以
未收敛错误退出，绝不计为完成的流动结果。v7 的完整单步另行运行。
