# Aphros 可选混合精度 AMG：16/32/64 单步验证

这次只增加独立 Aphros 参考构建的候选线性后端及运行脚本。
Cirrus 的生产求解器、原生八叉树和 GPU matrix-free AMG 没有改变。
原始 128 参考继续使用原可执行文件；本候选尚未被采用为 128 参考。

## 为什么尝试

对正在运行的 `aphros128_native_steady_seed_v1` 捕获完整线性调用的
只读日志前缀，在其中最近 300 次调用中，首次 AMG 求解占线性后端
时间的 83.93%，建立/查找缓存占 13.00%。当前参考使用扩展精度
AMG；日志里的 `factor-cache` 在这里缓存 AMG 预条件器，并非执行
LU 分解。单纯增加缓存容量不能消除主要耗时。

`validation/aphros/build_mixed_amg_reference.py` 从已验证的
`aphros_lazy_centers_v1` 独立复制源码，显式设置
`APHROS_TWISTED_DOUBLE_AMG=1` 时，才将近似线性求解切换为 double
AMGCL。未设置时仍执行原扩展精度路径。

原矩阵、右端项、兼容性处理及压力基准约束仍采用 `long double`。
只有近似求解用的矩阵转为 double；转换拒绝非有限值及非零系数
下溢为零。右端项先以扩展精度最大模归一化，再转为 double，
结果转换回扩展精度后恢复尺度。double AMG 内部相对容差为
`1e-13`，最多 500 次迭代；原路径内部容差仍为 `1e-18L`。

原有最多六轮扩展精度残差修正、体积归一化以及包括压力基准行在内
的全部原方程检查逐字保持。原方程残差超过原门槛时仍报错。
`mixed_precision.csv` 记录每次调用的原方程残差、修正轮数和线性
迭代数。因此，较松的近似求解容差并没有替换最终方程验收。

构建使用同一编译器执行全部 48 个编译单元的依赖扫描，只有
`src/linear/linear.cpp` 重编译，47 个已核实对象复用。实际变更的
头文件是 `sources/src/linear/twisted_direct.h`。独立范围审计确认
投影、切割几何、嵌入边界近似、显式/隐式输运等六份核心源码
逐字节不变。范围审计 v1 因文本结束标记匹配方式错误退出；
v2 修正审计器的搜索范围后通过，v1 失败记录也保留。

## 已完成的比较

三个运行均使用原参考的相同几何、配置、线程和存储选项，并从
零速度推进一个完整物理步。这里的 16、32 是背景网格的横向
分辨率，算例为三维扭曲细管；这些小网格比较不代表稳态或自适应
网格收敛验收。

| 运行 | 与原扩展精度 Aphros 的比较 | 线性调用 / 最多残差修正 |
| --- | --- | --- |
| 16，选项关闭 | 严格比较通过，六份输出逐字节相同 | 1560 / 原路径 |
| 16，选项开启 | 场量及实际面通量守恒通过；场量最大相对 L2 差 `4.4194e-15` | 1560 / 0 |
| 32，选项开启 | 场量及实际面通量守恒通过；场量最大相对 L2 差 `2.6332e-15` | 1107 / 1 |

开启选项的两组**严格比较均为失败**：输出及外迭代打印值不是
逐字节相同。既有 `check_aphros_precision_pair.py` 没有修改，完整
失败 JSON 保留；上表明确区分其中通过的场量/守恒子检查。
32 网格速度、压力、壁面剪切、面速度的相对 L2 差分别为
`1.0397e-15`、`4.9261e-16`、`2.6332e-15`、`8.8064e-16`。
实际存储的十六进制面通量使用高精度独立重建守恒，候选 32
的相对最大散度为 `3.1376e-11`，原参考为 `6.4937e-11`。

另以现有 `compare_twisted.py` 直接比较 Cirrus 保留的同一步结果，
沿用全部已有门槛，包括近壁速度、壁面剪切、共享面通量及守恒：

| Cirrus 与候选 Aphros | 速度相对 L2 | 压力相对 L2 | 切割单元速度相对 L2 | 壁面剪切相对 L2 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 16 | `7.1220e-10` | `2.5307e-10` | `1.4819e-9` | `3.8008e-9` | 通过 |
| 32 | `1.9010e-10` | `1.0263e-10` | `1.2537e-9` | `8.3977e-10` | 通过 |

Cirrus 输入分别为 `output/twisted/ours_proj16_output_dense_v1/step_0001`
和 `output/twisted/ours_proj32_steady_v1/step_0001`。后者目录名虽含
`steady`，本次只比较第一物理步。16 使用 GPU，32 为既有 CPU
结果，这不是两种硬件的性能对比。
