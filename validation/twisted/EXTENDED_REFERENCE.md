# 保持原几何的扩展精度 Aphros 路径

本检查点延续 `PRESSURE_PRECISION.md` 和 `ANDERSON_FAILURE.md` 的诊断。
离线全耦合压力重放已经通过；这里进一步构建完整原始 Proj 驱动，
但完整扩展精度流场对照和定常验收尚未完成。

## 几何保存与载入

`validation/aphros/twisted_geometry_state.h` 保存原 Embed 的全部 15 组
内部几何字段，包括 level set、类型、面多边形、面积、法向、平面、
体积、各中心、距离、位移及邻域体积和；同时保存索引范围、halo 状态、
全局网格尺寸和步长。载入时将原 double 值精确转换为 long double，
不重新调用切割几何初始化。访问这些字段只需在隔离的 Embed 头文件
增加 friend 声明，不改变类布局或原初始化算法。

`geometry_state_double_build_v1` 只编译新驱动，链接未重建的原 Aphros
静态库。16 和 64 的保存结果，其单元、面、壁面和多边形 CSV 均与已
完成的原始参考逐字节一致。16 的 double 保存/再载入也逐字节一致。

扩展精度驱动 v3 载入 16、64 后，完整状态转回 double 的二进制快照
与原快照逐字节一致；计算使用的单元体积、面面积、壁面法向、平面及
中心完全一致。16 首次要求所有导出顶点相等的检查未通过：原
`GetCutPoly` 在相同平面参数上使用更高精度重新计算，仅 axis=3 的
壁面显示顶点出现最多 2.776e-17 的坐标差异。未改变计算几何。

后续检查显式区分这项显示舍入：完整状态必须逐字节相同，所有计算
几何值和面多边形必须完全相同，只允许相同壁面顶点编号的坐标差异
小于四个 double epsilon 乘坐标/步长尺度。16、64 均通过。严格检查
的未通过记录同时保留。将 64 快照装入 16 配置的负例被拒绝，报错
`Geometry snapshot mesh differs`，没有生成流场。

## 独立构建过程

所有准备与编译都发生在 `twisted-baseline` 的新目录，未改动原源树
或共享静态库。`prepare_extended_reference.py` 记录原始与生成文件
哈希，`build_extended_reference.py` 记录实际编译命令、目标文件和
二进制哈希。各次尝试保留，未覆盖早先失败结果。

- v1：完整编译发现 7 项类型/平台问题，未链接。
- v2：45 个目标全部编译通过，链接缺少输出模块的标量实例及依赖。
- v3：48 个目标全部编译、链接通过，可实际载入原几何并运行原 CG。
- v4：保留标量精度的 AMG 版本全部编译、链接通过。

类型兼容修改为 long-double NaN 支持、将精确零/一常量写成 Scal、
块元数据及必要显式实例使用对应标量。Windows 兼容修改只修复一个
`defined` 拼写、将不可用的 CPU 亲和性报告写为 -1。原 Proj 的
压力、黏性、对流和时间推进表达式没有改写。

v3 明确禁止会丢弃额外精度的旧 double 验证后端，使用原始扩展精度
共轭梯度算法。v4 将既有原始行检查后端的矩阵、向量、AMG 和残差
运算均保留为 Scal，内部 Krylov 容差收紧到 1e-18，外部原始方程
残差检查保持不变。该线性后端仍需完整流场对照验证，不能仅凭编译
通过宣布正确。

两条 16 网格 dt=0.001、8 步运行分别位于
`navier_stokes_proj_n16_extended_cg_v3` 和
`navier_stokes_proj_n16_extended_amg_v4`。本检查点生成时它们仍在运行。
原始 64 定常参考也继续运行，没有被停止或覆盖。

## 实际 128 网格候选失败恢复

`ours_proj128_anderson_failure_2steps_v1` 已直接记录：第二物理步的
第二次迭代，四个候选均在 `anderson_fixed_point` 阶段失败，对应
压力调用 62 至 65。4000 次线性迭代后的真实相对残差分别约为
1.06142e-13、1.08777e-13、1.10151e-13、1.10311e-13，均未被接受。
随后原状态被恢复，第三次及后续迭代继续推进。保存了四个实际右端
及阶段元数据，主线性容差仍为 1e-13。

这证明原中断来自可选候选并已按预期回退。两步完整验收在此检查点
仍未完成，不能据此宣布 128 定常结果、独立参考对齐或网格收敛通过。
