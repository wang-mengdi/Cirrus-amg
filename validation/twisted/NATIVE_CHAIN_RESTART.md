# 从已续算的曲面管道状态继续恢复

`cirrus_projection_chain_restart_v3` 支持恢复链：父运行可以已经
从一个已验证的检查点恢复。每一段保留自己的实际 GPU 调用日志，
祖先的完整场文件、时间历史和恢复状态分别验证，不把续算段说成
从零启动的新轨迹。此次没有改变压力、黏性、BCG、壁面或粗细接口
离散；GPU 仍采用原生隐式算子和 AMG。

新工具独立放在 `twisted_chain_restart.py`、
`prepare_twisted_chain_restart.py`、`run_twisted_chain_solver.py` 和
`check_twisted_chain_native_run.py` 中，避免改动已有运行正在使用
的 v2 包装器。C++ 恢复入口新增 v3 格式识别；仍要求完整的七个
单元状态量与全部面通量、相同物理参数、网格尺寸和物理时间。

每个新检查点必须比直接祖先推进至少一个完整物理步。验证涵盖：
实际执行文件与配置、递归祖先输入、C++ 的 `restart_loaded.bin`、
所有前缀副本、重建网格及面顺序、继承的时间历史、完整固定点、
黏性残差，以及保留完整场各步的共享面通量守恒。循环引用被拒绝。
活跃父运行需要精确的 PID、创建时间、可执行文件和配置匹配，且
必须观察到更晚一步开始的写完屏障；否则需要真实成功结束记录。

当前恢复仍保持 dt 不变。MGS2/CGS2 的既有切换许可保留，物性、
算子、误差门槛和时间步不能借恢复改变。

## 初版问题及修正

初版完整场回归通过，但专门构造的真实父运行副本暴露了遗漏：
把继承历史第一步的时间加速度改为 123，仍通过初版检查。
`checks/chain_history_probe_v1/result.json` 保留这一失败证据。
最终实现逐项比较继承历史与祖先检查点，拒绝这种篡改。

`checks/chain_rejections16_v3/result.json` 的 18 项检查全部通过，
涵盖修改物性或 dt、放宽线性容差、无剩余步、伪造深度或祖先输入、
遗漏状态或前缀文件、状态变化后更新其哈希、真实 C++ 回写被改、
父运行遗漏执行祖先、继承历史被改、无物理推进，以及通过真实
父配置构造的循环引用。正常迁移检查点作为有效对照。

初版 128 只读验证累计重复读取约 190 GB 后被主动停止，仅停止
精确识别的 Python 验证进程，所有 CFD 求解器继续运行；该初版
128 检查不作为完整验证通过。最终工具在一次验证调用内复用文件
哈希：首次完整读取前后核对文件身份、尺寸及修改时间，每次命中
和结束时再次核对。发现变化立即失败，缓存不跨调用持久化。
v2 祖先验证只共享这层读取缓存，其算法和存储证明不变。测试还
覆盖缓存命中前变化及最后一次读取后变化，二者都被拒绝。
