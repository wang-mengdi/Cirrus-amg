# Aphros 定常计算的速度初始猜测

本检查点为隔离 Aphros 驱动增加可选初始速度入口，使用原有
`ProjArgs::fcvel`。压力、面通量、时间推进、投影、黏性、对流
和近壁离散仍由原 Aphros 实现执行。没有恢复外部压力或通量，
没有修改方程或设置速度为固定边界条件。新实验均位于
`D:\CirrusExperiments\cirrus-amg`。

## 实现与来源检查

`validation/aphros/twisted_initial_velocity.h` 读取完整规则网格
的流体掩码及三分量双精度初始速度，将值转换为参考使用的
`long double`。文件记录形状和网格间距，驱动将掩码逐单元
与加载的原几何核对。它填充周期 x 方向的两层 halo，非周期
方向域外及排除单元保持零值。读取后回写实际内部存储，运行
包装器核对回写与输入逐字节相同。

`prepare_initial_velocity_reference.py` 只改隔离树的 `driver.cpp`，
加入辅助头文件，原字段存储继续沿用已验证版本。全部 48 个
翻译单元重新编译，关闭 fast-math 和浮点收缩。实际构建为
`builds/aphros_initial_v1`，可执行文件 SHA256：
`2156fed7dcb8f20c1c6b6620f399cee3a7be4876db25f60c0c3878991f2ccfdd`。

配置必须明确设定 `vel_init twisted_seed`，并与运行参数指定
的初始文件一致。`run_aphros_initial_reference.py` 保存初始文件、
其生产者和数据来源哈希；PowerShell 包装器记录实际环境及
输入哈希，并在结束时检查输入未变。

独立读取测试验证了内部值、周期与非周期 halo、实际存储回写，
并拒绝 9 类错误输入：额外字节、形状错误、间距错误、与几何
不符的掩码、非法掩码值、NaN、排除单元非零值、周期设置错误
及截断文件。记录在 `checks/initial_velocity_loader_v2`。

关闭入口时，完整 16 网格第一步的六份输出逐字节一致，260 次
外迭代误差序列不变；原函数体、构建对象和几何来源验证通过。
报告为 `checks/aphros16_initial_off_pair_v1.json`。

## 已完成的 16 网格定常验证

`runs/aphros16_initial_one_v1` 使用原 Aphros 16 网格定常速度作为
初始猜测，仍由原投影流程初始化压力和通量。dt 为 0.005，
正常完成全部 128 步至 t=0.64。初始场回写逐字节一致，所有
输入保持不变。它在第一步仍有非零变化，说明初始场没有被
当作最终结果直接返回。

与原来从零启动的 `navier_stokes_proj_n16_steady_probe_v1` 对比：

| 量 | 相对 L2 差 |
|---|---:|
| 速度 | 4.017489830860015e-12 |
| 压力（消除常数规范） | 6.3793322561265105e-12 |
| 切割单元速度 | 1.1963228775570726e-11 |
| 壁面剪切 | 5.905760160282223e-12 |
| 所有面法向速度 | 3.798633789764427e-12 |

两者质量检查均通过；新运行以实际十六进制面通量复算的质量
相对 Linf 为 2.093715593500374e-13。最终速度变化率为
5.151376800009679e-14，小于保持不变的定常门槛。

报告 `checks/aphros16_initial_one_steady_v1.json` 验证了相同物理
配置（仅初始条件不同）、实际执行文件、历史原驱动的归档
源码、原共享库、加载几何、128 步时间序列及逐项场比较。
历史驱动的当前文件已演进，因此校验使用与原构建哈希一致的
归档字节，没有用当前源码替代当时编译的源码。

半幅初值 `runs/aphros16_initial_half_v1` 随后也完成了全部 128 步。
`configs/complete_initial16_pair_v2.py` 在实际进程结束后执行三者
比较，报告 `checks/aphros16_initial_steady_pair_v1.json` 通过。
半幅初值与从零启动的最终速度、压力、切割单元速度、壁面剪切、
面法向速度相对 L2 差分别为 8.6226e-13、1.1271e-12、2.3409e-12、
1.1013e-12、8.3379e-13；最终速度变化率为 8.4868e-13。
三者质量、定常性和场比较全部通过。后续完成记录存入
`results/native_prefix_restart_checkpoint`；原初值检查点保留当时
半幅运行尚未结束的历史记录。

## 64 网格定常实验

`scripts/prepare_aphros_initial_velocity.py` 将已完成的 Cirrus 64
定常速度转换到原 Aphros 网格：136120 个位置直接对应相同
中心，4096 个位置在八叉树粗单元内，以现有 32 邻点二次拟合
插值。最大拟合条件数约 14.13。几何平移和周期坐标使用现有
比较工具的转换。输出只是初始猜测，不作为独立基线结果。

初始文件在 `configs/initial_velocity64_native_v1`，其 SHA256：
`cc4415c1bd15401f7896f1498fb47fe92e013dd289840d053e78b6c74e88034f`。
`runs/aphros64_initial_native_v1` 已加载全部 140216 个流体单元，
并进入原 Aphros 定常推进；最终场对齐尚未完成。从零启动的
原 64 网格轨迹继续运行。

另外，上一检查点的 `runs/aphros64_zero_reset_v1` 已完成并通过
完整比较：六份输出逐字节一致，39 次外迭代误差序列一致。
该项报告为 `checks/aphros64_zero_reset_pair_v1.json`，证明原地址
清零的存储修改在完整 64 网格第一步保持一致。

本检查点没有解决 128 网格参考的内存限制，也没有完成空间
收敛、128 网格定常解或最终近壁精度验收。完整 goal 保持进行中。
